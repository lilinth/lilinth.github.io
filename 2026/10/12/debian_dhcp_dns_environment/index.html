Debian 12 部署 DHCP 与 DNS Server

1. 文档目的

在 Debian 12 上部署内网 DHCP 和 DNS 服务，实现：

  • DHCPv4：自动分配 IPv4 地址。
  • DHCPv6：自动分配 IPv6 地址。
  • DNS：接收和处理内网客户端的 DNS 查询。
  • 内网域名解析：支持手动配置 A、AAAA 等记录。
  • 服务独立运行，不依赖公网 DNS 或外部网络。

本方案使用：

组件 软件 作用
DHCPv4 Kea DHCPv4 IPv4 地址分配
DHCPv6 Kea DHCPv6 IPv6 地址分配
DNS Unbound DNS 查询处理及内网记录解析
IPv6 RA radvd 通告 IPv6 网络前缀及 DHCPv6 管理标志

注意：Kea DHCP 不提供 DNS 查询服务，因此需要额外部署 DNS Server。

8. 配置 Unbound DNS

8.1 设计原则

Unbound 负责监听 DNS 的 UDP/TCP 53 端口并处理 DNS 查询。

在纯内网环境中：

  • 可以解析配置在本机的内网记录。
  • 可以回答已有的有效缓存记录。
  • 没有公网连接时，不能保证解析未配置的公网域名。
  • DNS 查询收到响应不代表域名解析成功，必须检查 DNS 返回码及答案内容。

10. 防火墙与端口

如果服务器启用了防火墙，需要允许来自内网的以下流量。

服务 协议与端口 用途
DHCPv4 UDP 67 DHCP 服务器
DHCPv6 UDP 547 DHCPv6 服务器
DNS UDP 53 常规 DNS 查询
DNS TCP 53 TCP DNS 查询及较大响应
IPv6 RA ICMPv6 IPv6 网络配置通告

客户端 DHCP 使用的源端口通常为 UDP 68（IPv4）和 UDP 546（IPv6）。防火墙应按实际规则允许相应请求及响应。

RA 使用 ICMPv6，不是 UDP 端口。

DNS 应限制为内网访问，不要在没有访问控制的情况下将递归 DNS 开放给不可信网络。

12.4 其他注意事项

  • 如果服务器与客户端不在同一子网，需检查 DHCP Relay 和路由。
  • DHCPv6 不负责分配 IPv6 默认网关。
  • DHCPv4 与 DHCPv6 租约数据库相互独立。
  • DHCP 地址池不能与静态地址或其他 DHCP 服务器的地址池冲突。
  • 变更配置前应先备份，使用配置检查命令验证后再重启服务。
  • 如果存在多个 DHCP 服务器，必须确认它们的地址池、网段和职责，避免重复分配地址。

13. 部署验收清单

  • 服务器 IPv4/IPv6 地址正确且持久生效。
  • Kea DHCPv4 配置检查通过，服务运行正常。
  • 客户端能通过 DHCPv4 获取地址、租约及 DNS 配置。
  • Kea DHCPv6 配置检查通过，服务运行正常。
  • radvd 正常发送 IPv6 RA。
  • 客户端能通过 DHCPv6 获取地址和 DNS 配置。
  • Unbound 配置检查通过，UDP/TCP 53 端口监听正常。
  • 内网 A 记录查询返回 NOERROR 和正确地址。
  • 内网 AAAA 记录查询返回 NOERROR 和正确地址。
  • 防火墙仅允许预期内网访问 DHCP、DNS 服务。
  • 服务日志无持续性错误。
  • 租约文件清理与轮转过程无未解决的错误。

14. 最终架构

部署完成后，服务器提供三项核心功能：

  1. Kea DHCPv4：为客户端分配 IPv4 地址。
  2. Kea DHCPv6 + radvd：为客户端提供 IPv6 地址分配及必要的 IPv6 网络通告。
  3. Unbound DNS：接收内网 DNS 查询并解析配置好的内网记录。

该方案可以在不接入公网的条件下运行。对于未配置的公网域名，服务器不会因为部署了 DHCP 或 DNS 就自动获得解析能力。
