Debian 12 部署 DHCP、DNS 与 PXE Server

1. 文档目的

在 Debian 12 上部署内网 DHCP、DNS 和 PXE 服务，实现：

  • DHCPv4：自动分配 IPv4 地址。
  • DHCPv6：自动分配 IPv6 地址。
  • DNS：接收和处理内网客户端的 DNS 查询。
  • 内网域名解析：支持手动配置 A、AAAA 等记录。
  • PXE：向客户端下发引导服务器与引导文件名，并提供引导文件下载，用于验证网络引导链路。
  • 服务独立运行，不依赖公网 DNS 或外部网络。

本方案使用：

组件 软件 作用
DHCPv4 Kea DHCPv4 IPv4 地址分配
DHCPv6 Kea DHCPv6 IPv6 地址分配
DNS Unbound DNS 查询处理及内网记录解析
IPv6 RA radvd 通告 IPv6 网络前缀及 DHCPv6 管理标志
TFTP tftpd-hpa 提供 PXE 引导文件下载
引导程序 PXELINUX / GRUB2 BIOS 与 UEFI 客户端的引导程序

注意：Kea DHCP 不提供 DNS 查询服务，因此需要额外部署 DNS Server。PXE 相关内容见第 12 章，该章节以验证引导链路为目标，不包含系统安装与无人值守配置。

8.1 设计原则

  • 可以解析配置在本机的内网记录。

  • 没有公网连接时，不能保证解析未配置的公网域名。

10. 防火墙与端口

如果服务器启用了防火墙，需要允许来自内网的以下流量。

服务 协议与端口 用途
DHCPv4 UDP 67 DHCP 服务器
DHCPv6 UDP 547 DHCPv6 服务器
DNS UDP 53 常规 DNS 查询
DNS TCP 53 TCP DNS 查询及较大响应
IPv6 RA ICMPv6 IPv6 网络配置通告
TFTP UDP 69 客户端下载 PXE 引导文件

客户端 DHCP 使用的源端口通常为 UDP 68（IPv4）和 UDP 546（IPv6）。防火墙应按实际规则允许相应请求及响应。

RA 使用 ICMPv6，不是 UDP 端口。

TFTP 客户端只向服务器的 UDP 69 发起请求，实际的数据传输使用客户端随机分配的高位端口。如果防火墙没有状态跟踪，需要额外放行 UDP 高位端口的回程流量；如果防火墙按连接跟踪放行，通常只需允许 UDP 69。

DNS 应限制为内网访问，不要在没有访问控制的情况下将递归 DNS 开放给不可信网络。

环节 软件 说明

文件 路径
PXELINUX 主程序 /usr/lib/PXELINUX/pxelinux.0
PXELINUX 依赖模块 /usr/lib/syslinux/modules/bios/ldlinux.c32
Debian netboot 引导文件 /usr/lib/debian-installer/images/12/amd64/text/
GRUB2 EFI 网络引导程序 /usr/lib/grub/x86_64-efi/monolithic/grubnetx64.efi

关于 UEFI：Debian 12 的 syslinux-efi 包只提供 /usr/lib/SYSLINUX.EFI/efi64/syslinux.efi，不提供 pxelinux.efi，因此 UEFI 客户端无法像 BIOS 那样直接使用 PXELINUX。本章的 UEFI 路径使用 Debian netboot 镜像自带的 GRUB2。

grubnetx64.efi 是 GRUB2 的单文件网络引导版本，可以作为备选方案使用；本章默认使用 netboot 镜像自带的引导文件，原因是它们与内核、initrd 属于同一套构建，版本一致性更好。

12.6.1 引导信息的三种载体

载体 Kea 配置项 承载位置 客户端未请求时是否下发

12.9 分级验证

不要一次把所有条件都打开，按下面的顺序逐级验证，每一级失败都能定位到具体环节。

级别 目标 客户端现象 判断依据
L1 DHCP 只发地址、不发引导信息 PXE-E53: no boot filename received DHCP ACK 中没有 file 字段，说明 Kea 未下发引导文件名
L2 拿到引导文件名，但取不回来 PXE-E32: TFTP open timeout DHCP ACK 中 file 正确，但 TFTP 日志中没有请求记录
L3 取回引导程序 出现 PXELINUX 引导提示，或进入 GRUB2 菜单 TFTP 日志出现 Serving pxelinux.0 或 Serving .../bootnetx64.efi

12.10 故障排查

现象 可能原因 处理方式
PXE-E51: no DHCP servers were found 客户端没有收到任何 DHCP 应答 检查网卡链路与 VLAN、DHCP 服务状态、防火墙 UDP 67 / 68
PXE-E53: no boot filename received Kea 未下发引导文件名 检查子网级 next-server、boot-file-name；若依赖 Option 66 / 67，需确认客户端是否在参数请求列表中请求了它们，或配置 always-send
PXE-E32: TFTP open timeout 客户端拿到文件名但连不上 TFTP 检查 TFTP_ADDRESS、客户端与服务器是否同网段、路由与防火墙 UDP 69
PXE-T01: File not found TFTP 根目录下文件不存在或路径错误 用第 12.4 节的自测方法验证；--secure 限制只能访问根目录内的文件
PXELINUX 停在加载阶段或找不到配置 缺少 ldlinux.c32，或 pxelinux.cfg/default 不存在 确认两个文件都位于 TFTP 根目录，路径以 TFTP 根为基准
GRUB2 找不到内核 配置中的路径不是 TFTP 根目录绝对路径 改用 /debian-installer/amd64/linux 这类写法
内核启动但串口无输出 内核命令行缺少 console=ttyS0,115200n8 补上 console 参数，并确认 BIOS 中串口已重定向到 COM1
Secure Boot 客户端拒绝引导文件 客户端信任链不接受该 EFI 引导文件 关闭 Secure Boot 验证，或改用客户端信任的引导程序，详见仓库中的 WDS 签名问题文档
initrd 下载失败或中断 initrd 体积较大，TFTP 传输慢或被中断 先比对文件完整性，再考虑改用 iPXE + HTTP 传输

12.11 验收清单

  • tftpd-hpa 已启用并运行，UDP 69 监听在预期地址。
  • TFTP 根目录结构与第 12.5 节一致，文件对 tftp 用户可读。
  • Kea DHCPv4 配置检查通过，DHCP ACK 中包含正确的 siaddr 与引导文件名。
  • BIOS 客户端能加载 PXELINUX 并继续引导内核。
  • UEFI 客户端能进入 GRUB2 菜单并加载内核。
  • 客户端同时能通过 DHCP 获取地址与 DNS 配置，与第 9 章的验证结果一致。
  • 验证结束后客户端未执行实际安装。

12.13 后续可选扩展

  • iPXE + HTTP：用 iPXE 取代 PXELINUX / GRUB2 直传，内核与 initrd 改走 HTTP，大文件传输更快，也便于做菜单和变量。Debian 12 的 ipxe 包提供 /usr/lib/ipxe/ipxe.efi、undionly.kpxe 等文件。
  • 无人值守安装：在 grub.cfg 或 pxelinux 配置中补充 preseed / kickstart 参数。
  • 按 MAC 区分引导：PXELINUX 支持 pxelinux.cfg/01-<MAC> 一类的文件名约定；GRUB2 默认不按 MAC 区分，需要在 grub.cfg 中自行实现查找逻辑后再 source 对应文件。
  • IPv6 PXE：见第 12.7 节的限制说明，需要单独实测。

13.4 其他注意事项

  • 如果服务器与客户端不在同一子网，需检查 DHCP Relay 和路由。
  • DHCPv6 不负责分配 IPv6 默认网关。
  • DHCPv4 与 DHCPv6 租约数据库相互独立。
  • DHCP 地址池不能与静态地址或其他 DHCP 服务器的地址池冲突。
  • 变更配置前应先备份，使用配置检查命令验证后再重启服务。
  • 如果存在多个 DHCP 服务器，必须确认它们的地址池、网段和职责，避免重复分配地址。

14. 部署验收清单

  • 服务器 IPv4/IPv6 地址正确且持久生效。
  • Kea DHCPv4 配置检查通过，服务运行正常。
  • 客户端能通过 DHCPv4 获取地址、租约及 DNS 配置。
  • Kea DHCPv6 配置检查通过，服务运行正常。
  • radvd 正常发送 IPv6 RA。
  • 客户端能通过 DHCPv6 获取地址和 DNS 配置。
  • Unbound 配置检查通过，UDP/TCP 53 端口监听正常。
  • 内网 A 记录查询返回 NOERROR 和正确地址。
  • 内网 AAAA 记录查询返回 NOERROR 和正确地址。
  • 防火墙仅允许预期内网访问 DHCP、DNS 服务。
  • 服务日志无持续性错误。
  • 租约文件清理与轮转过程无未解决的错误。
  • tftpd-hpa 运行正常，UDP 69 端口监听正常。
  • DHCP 应答中包含正确的 TFTP 服务器地址与引导文件名。
  • BIOS 客户端能加载 PXELINUX 并继续引导内核。
  • UEFI 客户端进入 GRUB2 菜单并能加载内核。

15. 最终架构

部署完成后，服务器提供四项核心功能：

  1. Kea DHCPv4：为客户端分配 IPv4 地址，并下发 PXE 引导服务器与引导文件名。
  2. Kea DHCPv6 + radvd：为客户端提供 IPv6 地址分配及必要的 IPv6 网络通告。
  3. Unbound DNS：接收内网 DNS 查询并解析配置好的内网记录。
  4. tftpd-hpa + PXELINUX / GRUB2：提供 PXE 引导文件下载，完成网络引导链路。

该方案可以在不接入公网的条件下运行。对于未配置的公网域名，服务器不会因为部署了 DHCP 或 DNS 就自动获得解析能力。

第 12 章的 PXE 部分用于验证引导链路，客户端最终停在 Debian 安装器界面，并不执行系统安装。
